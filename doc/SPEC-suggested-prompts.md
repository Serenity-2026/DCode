# 后续提问建议

- 每次正常回答完成后，使用本轮同一服务、协议和模型后台生成至多一句建议。失败、停止及没有正文的回答不触发请求；启动应用不补发旧回复的建议请求。
- 请求独立于 Agent，不携带工具，不占用聊天生成状态。仅发送最近三轮成功问答正文，每条问题最多保留末尾 3000 字符、回复末尾 5000 字符；不附加文件快照、推理和工具结果。输出上限 512 token，总等待上限 15 秒。
- 模型以用户口吻承接未完成事项，不能编造问题、重复已完成事项或回答建议本身。返回 JSON `{"suggestion":"一句建议"}`；没有自然下一步返回空字符串。只接受最多 160 字符的非空单行文字，格式错误、超时或服务失败均静默放弃。
- 建议保存在 assistant 消息的可选 `suggestedPrompt` 字段中，兼容原 schema 4 数据。通过现有流事件通知，后台更新不改变会话排序；建议字段不参与聊天上下文或上下文用量估算。
- 只有当前会话最后一条消息为已完成回复、输入框为空且没有附件时，才把建议作为灰色占位文字，显示“Tab 采纳建议”。普通 Tab 填入草稿，Shift+Tab 保持焦点导航；输入法组词和组合快捷键不采纳。Enter 不发送尚未采纳的建议。
- 用户输入内容后建议隐藏，清空后可重新显示；采纳后仍可编辑。建议结果从不覆盖草稿。切换会话显示对应回复的建议，不串用其他会话结果。
- 每个会话独立取消建议请求。发送新问题、重新生成、停止、删除、退出账号或关闭窗口会取消相关请求，并通过账号和最后回复 ID 校验丢弃迟到结果。切换会话不取消后台请求。
- 建议请求的实际 Token 增量计入所属回复的用量记录，每个请求独立去重；未报告 Token 的请求纳入缺失数量。已收到的用量在取消后保留。主回答的起止时间不延长，后台建议不计入最长任务耗时。

## 验证范围

针对性单元测试覆盖双协议无工具请求、上下文限额、有效及空结果、失败与超时、取消和迟到结果、会话与账号隔离、用量去重、持久化及旧格式兼容。Electron 场景覆盖灰色提示、Tab 采纳、Enter 防误发、草稿保护、附件隐藏、切换会话和重启恢复。
