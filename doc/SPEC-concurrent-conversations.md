# 多会话并行任务

## 范围与行为

同一账号可在会话 A 运行时切换到会话 B 并启动第二个任务，A 在后台继续生成；同一会话仍只运行一个任务。切换页面只改变当前选中的会话，不改变后台任务的身份、模型配置、目录或取消信号。保留现有 AgentTool / WorkspaceTool / ToolRuntime.bind 契约，不增加线程、任务队列或同一会话多任务。

每个会话拥有独立的 AgentSession、Agent 和 ToolRuntime，工具定义和无状态 AgentLoop 可以共享。AgentSessions 按 conversationId 管理运行实例，app 注入实例工厂；AgentSession/Agent/Loop 不依赖管理器。每次任务启动固定所选模型配置，后台任务不受之后模型选择影响。目录仍由会话附件恢复到该会话自己的 ToolRuntime。

发送可以显式携带 conversationId（null 创建新会话），停止必须携带 conversationId，主进程检查账号归属。同一会话重复发送或重试拒绝；停止当前会话不取消其他会话。IPC 只在请求准备及同步状态修改期间短暂互斥，不用长时间模型生成阻塞导航、附件和其他会话发送。

运行中会话允许查看、切换和重命名，删除必须先停止；其他会话可以正常删除。退出账号、关闭窗口或退出应用时停止全部任务，等待消息保存后完成原操作。全部停止期间拒绝新任务，重复关闭或退出仍等待同一次停止，不提前销毁。停止或最终保存失败时汇总报告并保留窗口/应用，允许重试；空闲会话也再次保存。临时资源按各自 ToolRuntime 归属逐个清理，失败目录保留登记并汇总路径/原因，不阻止其余目录清理。

## 状态与界面

活动会话 ID 是导航状态，不是任务 ID。AgentSession 保存目标会话/消息 ID，每次事件从仓库重新定位对象，避免其他操作事务回滚替换仓库对象后，流式更新继续写到旧引用。现有 JSON 仓库同步事务和原子保存继续使用，不新增存储格式或后台任务恢复；重启遗留 streaming 仍标记 stopped。

renderer 按 conversationId/messageId 合并所有会话的流事件，切换与发送不清空其他任务的事件缓存。输入框与停止按钮使用当前会话状态；导航、新对话和账号退出不因其他生成任务而禁用。侧栏用运行图标表示后台任务。关闭窗口仍停止任务，不新增托盘后台运行。

同一绝对路径的 write/edit 继续共享文件队列；bash 不受此队列约束，不引入工程锁或自动 worktree。

## 验证

验证两个真实 Agent 同时运行且目录、消息、模型配置和取消信号隔离；停止 A 后 B 继续完成；同会话重复发送拒绝、跨账号发送/停止拒绝、运行中删除拒绝、全部停止阻止新任务、事务失败后两个流仍写回当前仓库。Electron E2E 从界面运行 A、切换 B 并发送、分别停止/完成，再验证退出保存；保留全部已有回归，不开启真实服务 smoke。
